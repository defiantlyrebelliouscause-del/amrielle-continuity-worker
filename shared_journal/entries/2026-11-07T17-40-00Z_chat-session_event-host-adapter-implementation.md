# Event-driven host adapter implementation

- **Date:** 2026-11-07 (UTC)
- **Methods:** Reviewed PR #76 and the existing SQLite controller; added a signed HTTP event receiver, a database-backed idle-deadline poller, consent revocation, and signed worker claim/checkpoint/failure endpoints. Added HTTP-level regression tests and updated deployment documentation. Queried GitHub Actions for validation status.
- **Established in this run:** The repository now contains `idle_event_server.py`, which accepts HMAC-SHA256-authenticated JSON events at `/v1/sessions`, `/v1/activity`, and `/v1/consent`; its scheduler loop polls persisted activity deadlines and enqueues idempotent jobs. Signed endpoints expose job claiming, checkpointing, and failure reporting. Session identifiers are opaque and the adapter does not store message bodies. The latest PR head is `927cdd36b45f9c60e3ce3d93eb340b458818cf7b`. PR #76 remains open and in draft.
- **Validation:** The earlier controller-only commit passed 119 repository regression tests (run 42396628993). The newer HTTP-adapter commits have GitHub Actions runs queued behind an older in-progress PR validation; therefore the new adapter and its HTTP tests are **not yet verified by CI**. No local execution is claimed.
- **Confidence:** High that the source files and PR commits exist (direct GitHub API read); moderate that the design is internally coherent; unverified runtime correctness pending CI.
- **Limitations:** This is not deployed. The server must run on an operator-controlled host behind TLS, network access controls, and a process supervisor. The host application must actually emit authenticated human-activity events. This repository has no access to ChatGPT's private conversation event stream and cannot independently detect ChatGPT conversation inactivity. The current shared HMAC secret is a prototype trust boundary, not production multi-tenant identity. No model/tool execution consumer is deployed or connected.
- **Contradictions and bias check:** A functioning event receiver is not the same as a functioning ChatGPT integration. A successful GitHub workflow on the earlier controller revision does not validate the later HTTP adapter. Creating files and opening a PR does not mean the service is running.
